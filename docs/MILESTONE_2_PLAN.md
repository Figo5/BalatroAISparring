# Milestone 2: observation and legal action boundary

Architectural authority remains INTEGRATION_PLAN.md. M1 was accepted at 8bcccab. No game/server launches, live Mods writes, AI strategy/search/evaluation or M3 work. Astra owns acceptance; DeepSeek V4.1 Flash High implements; Claude Opus 5.5 High reviews actual source/diffs.

## Interfaces and invariants

1. Trusted integration captures a fresh, narrowly selected UI-visible frame from the **AI staged runtime only**. No traversal/copy of arbitrary G/MP trees. An explicit runtime role and supported decision context are prerequisites. No seed is exposed, including benchmark/user seeds. Unknown visibility, unsupported state or missing authoritative legality evidence denies the field/action. Runtime capture remains disconnected from mod startup until staged-isolation gates pass.
2. `AIObservation` is versioned, schema-allowlisted and phase-specific. It has no functions, userdata, metatables, shared live references, arbitrary config/ability tables or hidden IDs. Stable references are observation-local zone ordinals, never engine IDs/memory addresses. Own face-down identities are redacted. Deck information is aggregated from legitimately known public information, never current draw order. Current shop/pack views require their active visible context. Match-complete does not expose end-game private dumps.
3. Canonical observation content is immutable internally. Exported data is an isolated copy; optional proxy protection is secondary. Canonical serialization uses explicit types, stable field ordering, bounded strings/arrays/depth and locale-independent safe integers; displayed scores/timers are strings. Reject nonfinite/fractional unsupported numbers, cycles, aliases with unexpected shape, metatables and ambiguous arrays. Unknown input fields are never traversed. Hash is deterministic across Lua 5.1/LuaJIT; any noncryptographic hash is a diagnostic checksum, never an authorization/freshness check.
4. Legal actions are plain typed bounded records, with deterministic identity from the entire canonical action (not a collision-prone hash alone). The generator consumes only sanitized observation. Phase/resources/zone references/limits/slots must agree, and engine-dependent conditions require trusted affordance evidence reflecting legitimate UI interactions. Never assume one vanilla rule implements every modded card. Unknown/unsupported affordances yield no action. Enumeration is bounded and reports overflow explicitly. Composite order changes may use elementary moves; document incompleteness instead of silently pretending exhaustive enumeration.
5. A trusted broker binds each decision to an independent session/revision token outside the observation content. Submission checks exact structure, current token, fresh observation/candidate membership and engine validation; stale/ABA/replayed/forged actions fail. A checksum alone never authorizes execution. Real execution stays disabled in M2; only injected test doubles demonstrate the contract. No raw writes or gameplay callbacks are added.
6. A restricted policy-environment interface proves a future decision module cannot import integration, read globals/files/network/debug/RNG, or obtain closure environments. It receives only copied sanitized observation and legal actions. No real policy is implemented. Source must be text-only and bounded; runtime execution is instruction-bounded, with hooks restored on failure. This is a capability boundary for project-owned software, not a claim of memory-safe isolation against arbitrary hostile Lua. Production process/memory isolation stays a launcher prerequisite.

## Scope decisions

- Final reviewed deck projection is total-only. Rank/suit maps are withheld until a deck-preview-equivalent specification accounts for unknown and wheel-flipped cards; subtraction must not reveal hidden identities.

- Seed identifier is excluded even when user-visible: the already accepted plan forbids prediction from it.
- Opponent visibility follows inspected Multiplayer UI (masking, readiness, displayed score/hands, timer presence/threshold/precision and location settings). Never use raw real_score, inactive timer order or last_timer as policy data. Source evidence goes in M2_SOURCE_MAP.md.
- Trusted UI-view/affordance injection is allowed for engine-dependent interactions that cannot be safely determined without running callbacks. These are narrow explicit data/certification interfaces, not arbitrary provider objects passed to policy. Such adapters must be labelled fixture-only/unwired until real-game validation.
- Do not add calls to can_use/can_play/etc while enumerating hypothetical actions: these can depend on mutable globals or have side effects. A future authoritative adapter is responsible for fresh legal UI validation behind the broker.
- M1 bootstrap remains inert. New boundary modules can be exercised entirely via fixtures; no live game capture is necessary for this milestone.

## Acceptance evidence

Privacy fixtures must poison hidden fields, nested callbacks, metatables, cycles, future deck/shop/pack/RNG/opponent state and stale observations. Independent hidden-state perturbations must leave visible serialization/hash/actions unchanged. Mutation must not affect any source or stored observation. Determinism covers insertion order, repeated construction and cross-runtime outputs.

Legal fixtures cover all supported phases/action types, credit affordability, capacity/negative-slot exceptions only when certified, blocked/expired/completed state, empty/oversized/duplicate/foreign card selections, missing shop/pack/consumable targets, ordering and phase mismatch. Broker tests cover stale revision, replay, changed fresh resources, forged fields/IDs and validator failures without any mutation. Missing authoritative evidence fails closed.

Seeded synthetic property tests check schema/identity/legality/bounds/determinism; the fixture PRNG is independent of game RNG and never exposed to policy. Benchmark typical fixtures and report build/enumeration time, canonical byte size and approximate allocation separately from game performance.
