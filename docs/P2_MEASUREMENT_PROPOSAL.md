# Remaining native P2 stimulus design — proposal, not implementation or approval

The reviewed P2 gate requires actual initial-failure, connection-closure and keepalive/reconnect behavior, original timeouts and bounded retries, pinned loopback only, and zero live-file changes. The current `measure --phase P2` chooses a proven-dead port and starts MP. That can exercise initial connect failure, but a connection that never opens cannot exercise connected keepalive failure. Merely adding observer fields cannot complete native P2.

Source facts: pinned `work/reference/mp/networking/socket.lua` defines 10-second connect timeout, reconnect delays 2/4/8 seconds, and keepalive initial20/retry5/count4. Initial connect failure returns false. The closed-receive branch compares `error == "close"`; actual library behavior must be observed, not silently patched. Keepalive failure closes the socket then calls the same original `tryReconnect`. No change to these semantics is proposed.

Before implementing a broader stimulus driver, obtain Claude review of the smallest evidence-compatible approach. Candidate: retain initial-failure evidence from a genuine dead-port measurement, then use a tool-owned 127.0.0.1-only test listener that accepts and either closes or remains silent for the connected-failure scenarios. This listener belongs only to measurement, never to MATCH adjudication. It must never bind a remote/wildcard/admin port, send official requests, or mimic an opponent. Preserve the pinned original Multiplayer server for MATCH.

Open design choices requiring review: (1) bind multiple independently closed measurement sessions/subreceipts without weakening immutable certificate IDs and exact tool/content bindings, or (2) explicitly consume initial-failure observations from the existing dead-port P1B gate and connected-failure observations from P2, with source/mode/nonce and path binding at both receipts. Do not pick an option merely to make a certificate pass. Every applicable path needs actual observations, cleanup, before/after live checks and immutable copied artifacts. A fixtures-only branch test is regression evidence, not a native gate pass.

The next code review should first assess the implemented source observer and phase/port/stimulus binding. Then review the proposed native stimulus/evidence workflow. No actual game operation is authorized by this note; all previous backup/process/review preconditions remain.
