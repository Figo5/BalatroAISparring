# Terminal transport retention amendment

Architecture released after Claude Opus 5.5 High's conditional review and Astra's H1/H2 text amendments. No implementation/native acceptance.

The actual local server leaves isInGame true after sending winGame/loseGame (actionHandlers.ts). Lobby.disconnect consequently sends enemyDisconnected when the host terminates the defeated AI. The actual Multiplayer enemyDisconnected handler displays a reconnection overlay even after a win. Closing the whole server earlier also risks the client's own reconnect overlay. Neither action should precede the Player's opportunity to inspect its completed result.

For successful, authoritative human_end completion with leave_human_visible enabled, retain the terminal AI process and its Multiplayer connection alongside the already retained Player, server and service until the Player closes, ONLY if the service reports ai_end_received with a terminal result, result_conflict is false, and the owned AI is still running. The AI policy is stopped by the existing trusted terminal path; the engine owns win/loss and MP connection keepalive. Do not suppress or replace disconnect handlers or server win/life logic. Await the bounded AI receipt as before; if the receipt is missing when grace expires, conflicts, or the AI has exited, use the current immediate owned-AI teardown and honestly accept a possible real disconnect overlay. Do not relaunch or reconnect a genuinely exited AI. An AI exit during verified terminal retention does not fail the completed result or trigger a relaunch.

Once the retained Player has exited: (1) terminate the owned AI while the server is still up; (2) wait within the existing bound and require _owned_exit_proven(); on failure return through _finalize_refused_closure("session_closure_unproven"), retaining ownership and the open record for guarded acknowledge/retry; (3) stop server then service; (4) run _post_verifier, check live is closed, record the real verdict against the retained session, then _retire_session. Never reach a measured success with a still-running owned AI. Keep all handles until closure is measured. Preserve current live-game-appeared, human-exit deadline, user stop, failed closure/retry/lockout and ownership guards. A stop or failure uses the existing explicit owned-process teardown; never touch unrelated or live user processes. Mid-match disconnect/AI exit is still an abnormal failure. A terminal AI crash may still show a real disconnect and must not be fabricated into a normal connection.

Verification must reproduce the actual server disconnect behavior on normal AI termination, demonstrate that retained completed clients do not produce the false countdown, and retain a positive-control mid-match disconnect. Cover successful human_end with AI receipt/no receipt/conflict/exited AI, AI exit during retention, already closed human, explicit cleanup, human wait timeout, live game appearing, stuck AI and certificate finalization/retry ordering; leave_human_visible=False remains unchanged. Runtime fixtures establish that CLOSED/ENDED/ABORTED or heartbeat-aborted replies in terminal state never restart policy, leave_local, remove the send guard or invoke shutdown.

Native normal win and loss must each show the Player result and retain both connections for at least 90 seconds, exceeding the approximately 35/40 second server/client keepalive windows. A passive human-runtime logger counts inbound enemyDisconnected, reconnecting and stopGame without suppressing anything. Require zero such disruptive events during verified normal retention, followed by proven owned exit and zero live tree diff. A mid-match AI termination positive control still produces enemyDisconnected and host role_exited failure. Recheck test_supervisor_success_retains_human_and_keeps_server_until_exit, new-ticket/daemon-stop retention tests, astra_service_lifecycle, astra_host_runner_native, astra_host_failed_close and astra_p2_retained_identity. Rematch in a retained terminal window is unsupported; direct the Player to close and start a new practice session, and ensure terminal actions cannot restart the stopped policy. This is an offline lifecycle change, not a scoring/rules change.
