This is a named local draft profile; do not claim equality with the current Discord bot or its private queue probabilities. The pending optional question's 3–2–2 answer would be an explicit user override if actually submitted.

Preferred boundary: complete the draft in the existing Player practice menu before the closed-game launch request. This avoids extending session attestation deadlines around an attended draft. The host owns a bounded draft state machine over its existing authenticated loopback control channel; the UI renders only public draft state. It shows Player/AI turn order, current required count, remaining deck/stake options, selected bans and final choice. Human selections require real callbacks. The AI chooses only on its own turns, using public combinations and documented deck preferences, with no gameplay seed or hidden game state.

Generate unique valid combinations from a curated, source-validated list of supported decks/stakes available identically in both roles. Include the current Ranked-compatible stake subset and native Multiplayer decks where verified. Do not pull arbitrary registered content mods into the pool. No actor field is accepted: the host derives the actor from turn state, and computes AI turns itself. Apply the final selection using a scoped pre-force wrapper after the real lobby reset and before the first lobby-options send, following the existing trusted seed-wrapper pattern. Map deck key to actual name and stake key to actual index on both roles; refuse missing, mismatched or clamped stakes. ## Pacing and reporting

Normal currently passes zero delay to the loop. Thinking occurs as a dwell BEFORE the broker issues a token or the policy is asked. After the dwell, capture, request and submit immediately (production post-response pacing remains zero); retain exact canonical revalidation. Ranked exposes changing opponent scores and location, so holding a captured choice for seconds could repeatedly go stale and livelock.

Use a trusted primitive readiness/phase probe, with no policy data expansion for pacing. Default dwell by decision phase: card/PvP choices 4 seconds, shop choices 6 seconds (first shop inspection 8), booster choices 4, blind selection 2. Instant has zero thinking dwell and still retains animations. These are tuning defaults from sparse observations. If the AI's own visible active timer has R seconds remaining, cap dwell at min(base, max(0,R-2), 0.2*R). Never modify Ranked's timer or borrow hidden/opponent data. Carry elapsed dwell through state changes and stale retries until the current logical decision commits; cap total dwell at 8 seconds. Changes in opponent location must not restart it. Reset after a committed action or match reset, and cancel on terminal/disconnect. No-action/empty/transient captures must not restart a full dwell forever. Both dwell and legacy scheduled paths run terminal/wait checks every update. Preserve normal animations, control advancement, timeouts and the broker's full equality check. Controlled-clock tests include a continually changing opponent location, phase changes, own timer cap, terminal-during-dwell, and no stale dispatch.

Count a refused decision once per delivered sequence and only for the existing receipt set (stale, dispatch failed, response rejected), in the same once-only receipt path. Keep idle, transient, empty, no-action and wait counters separate and bounded. Version the runtime receipt-counter summary so historical ai_rejected totals are not mislabelled as comparable counts. In the playtest 118 decisions were accepted and seven were stale; 77,404 includes idle frames. Do not alter loop return-code contracts. The Glass estimator projects the effective public own-card multiplier from the engine, supporting Standard x1.5 and vanilla/Major League x2 without adding hidden fields or hardcoding a global Ranked constant.

The separately reviewed RANKED_TERMINAL_RETENTION_PLAN.md governs completion. Actual source confirms that terminating AI after human_end while the server remains isInGame sends enemyDisconnected; stopping the server first risks self-reconnection. Retain the completed AI connection with the Player/server/service only after a non-conflicting terminal AI receipt and verified owned-AI liveness. Missing/conflicting receipts keep current immediate teardown. After Player exit, prove owned AI exit before server/service retirement and real certificate after-diff; retain failed closure for guarded retry. Native win and loss must each retain for 90 seconds with passive disruption-event counts, and real mid-match disconnect remains an abnormal positive control. Prior evidence does not prove the exact overlay the user saw. Do not suppress handlers, fabricate a disconnect cause or alter Multiplayer win/life logic.
